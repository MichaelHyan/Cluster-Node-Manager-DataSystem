# Cluster Node Manager DataSystem (CNMD)

## 集群节点式对话管理系统

CNMD 是一个创新的对话管理系统，旨在解决当前对话式大模型存在的痛点：对话给出了不符合预期的答案，无法回退，继续对话容易被先前对话记录带跑。

CNMD 借助如其名字般雷厉风行的类节点会话管理模式可缓解该情况。

## 功能特点

- **节点式对话管理**：支持保存、加载和回退对话状态
- **事件驱动模式**：大模型可选择操作Agent工具而不直接回答用户
- **文件操作能力**：提供目录查看、文件读写、删除等操作
- **命令执行功能**：支持系统命令的执行和结果获取
- **多模式支持**：提供数据队列模式和Web UI模式
- **自动日志记录**：每次使用将自动创建日志并记录会话内容

## 事件模式引入

不同于传统的大模型对话，事件模式下大模型可选择操作Agent工具而不直接回答用户并等待指令，直到完成任务，从用户下达命令到大模型完成命令之间的过程为一个事件。

如仅对话，则一次回复为一个事件。

## 节点操作

在每次事件开始前，可存档当前对话记录。

```
    #node save eventb
          ↓
eventA-eventB-eventC-eventD->...
(init)    |
          | -> #node load eventb
          |
       enentE->eventF->....
      (->eventB)
```

### 可用命令

操作指令可使用#help查看。

1. **节点操作 (#node)**
   - `#node save <节点名称>` - 保存当前对话状态到指定节点
   - `#node load <节点名称>` - 从指定节点加载对话状态
   - `#node list` - 列出所有已保存的节点
   - `#node backward <轮数>` - 回退指定轮数的对话（默认回退1轮）

2. **系统命令**
   - `#backup` - 备份当前工作目录
   - `#help` - 显示帮助信息

## Agent模式

CNMD同时引入了少量文件操作能力，大模型可在一定范围内完成任务。

使用前在config.json中将base_path改为需操作的文件根目录。

使用前请注意备份，哪怕是使用其他Agent工具时。

CNMD内置了备份功能，亦可使用。

## 使用模式

### 数据队列模式

当前使用的方式，返回信息将写入msg_stack，可逐步读取，适于流式输出。

### Web UI模式

将在本地启动网页前端，允许同一局域网下的设备访问，同时发送的消息会被CNMD处理并返回。

启动Web UI模式：
```bash
python webui.py
```

然后访问 http://localhost:5000 或局域网内的其他设备访问 http://[服务器IP]:5000

#### ！！【开发者提醒】！！

如果5000端口无法使用，可自行创建或尝试8000/8080/3000这三个端口，都可一定程度的绕过防火墙，并处于空闲

由于本项目使用的是http协议，基于现代互联网攻防体系的设定，所有防护软件（或插件）都会对http协议的网址进行提醒或者拦截，请各位不要担心，cnmd是一个绿色健康的项目（确信。

## 配置说明

在使用前，请编辑config.json文件进行配置：

```json
{
    "API_KEY": "your_api_key",
    "BASE_URL": "https://api.openai.com/v1",
    "MODEL": "gpt-3.5-turbo",
    "base_path": "D:/git/",
    "break": true
}
```

- **API_KEY**: OpenAI API密钥
- **BASE_URL**: API基础URL
- **MODEL**: 使用的模型名称
- **base_path**: 文件操作的根目录
- **break**: 是否在重复命令时中断执行

## 日志

每次使用将自动创建日志并记录会话内容。日志文件保存在`logs`目录下，以时间戳命名。
