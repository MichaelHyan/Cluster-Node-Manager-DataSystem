## Cluster Node Manager DataSystem (CNMD)
## 集群节点式对话管理系统

目前对话式大模型存在痛点：对话给出了不符合预期的答案，无法回退，继续对话容易被先前对话记录带跑。

CNMD借助如其名字般雷厉风行的类节点会话管理模式可缓解该情况。

### 事件模式引入

不同于传统的大模型对话，事件模式下大模型可选择操作Agent工具而不直接回答用户并等待指令，直到完成任务，从用户下达命令到大模型完成命令之间的过程为一个事件。

如仅对话，则一次回复为一个事件。

### 节点操作

在每次事件开始前，可存档当前对话记录。

```
    #node save eventb
          ↓
eventA-eventB-eventC-eventD->...
(init)    |
          | -> #node load eventb
          |
       enentE->eventF->....
      (->eventB)
```

操作指令可使用#help查看。

### Agent模式

CNMD同时引入了少量文件操作能力，大模型可在一定范围内完成任务。

使用前在config.json中将base_path改为需操作的文件根目录。

使用前请注意备份，哪怕是使用其他Agent工具时。

CNMD内置了备份功能，亦可使用。

### 操作台/接口模式

主程序(CNMD.py)允许了两种操作模式。

输入-输出模式：
 - 将CNMD作为单独方法调用，输出时将所有回复一次性发回。

数据队列模式：
 - 当前使用的方式，返回信息将写入msg_stack，可逐步读取，适于流式输出。

### 日志

每次使用将自动创建日志并记录会话内容。
