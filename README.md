# Cluster Node Manager DataSystem (CNMD)

**集群节点式对话管理系统 — 让 AI Agent 拥有文件操作、终端执行、网络访问与多模态处理能力**

## 📖 项目简介

CNMD 是一个创新的 Agent 型 AI 对话管理系统，旨在解决当前对话式大模型存在的核心痛点：**对话给出了不符合预期的答案，无法回退，继续对话容易被先前对话记录带偏。**

CNMD 借助类节点会话管理模式，支持对话状态的保存、加载与回退，让用户可以灵活地在不同对话分支间切换。同时，CNMD 赋予了大模型文件读写、终端命令执行、网络爬虫、多模态处理等 Agent 工具能力，使其能够真正完成工作任务而非仅仅对话。

## ✨ 核心特性

- **🔗 节点式对话管理**：支持保存、加载和回退对话状态，像 Git 分支一样管理对话走向
- **⚡ 事件驱动模式**：大模型可自主调用 Agent 工具链（文件操作、终端、网络），循环执行直到完成任务
- **🧠 记忆数据库系统**：支持对话记忆的智能提取、持久化存储、混合检索与自动整理，让 Agent 拥有长期记忆
- **📁 文件操作能力**：提供目录浏览、文件读写、删除、备份等完整操作
- **💻 终端命令执行**：支持 CMD / PowerShell 命令执行与结果获取
- **🌐 网络访问能力**：内置网页抓取、Ping 检测、自定义 Header 等网络工具
- **🖼️ 多模态支持**：支持图片、音频、视频的原生多模态处理
- **🤖 子任务系统**：支持将复杂任务拆分为多个子任务，由独立子智能体并行执行
- **🎯 技能模块系统**：可扩展的 Skill 模块架构，支持动态加载技能文档
- **💬 多端接入**：支持命令行、Web UI、微信三种交互模式
- **📝 自动日志记录**：每次会话自动创建日志并记录完整对话内容
- **🎭 人设系统**：支持加载不同人设与人格，适应多种对话场景

## 🚀 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

依赖包含：
- `openai` — LLM API 调用
- `flask` + `flask-socketio` — Web UI 服务，非必须
- `requests` — HTTP 请求
- `pycryptodome` — 微信文件加解密
- `qrcode` — 终端二维码显示

### 2. 配置

在`config.json`中填入你的 API 信息：

```json
{
    "API_KEY": "sk-your-api-key",
    "BASE_URL": "api-base-url",
    "MODEL": "model-name",
    "base_path": "workspace-path",
    "lang":"zh_cn",
    "break": true
}
```

| 配置项 | 说明 |
|--------|------|
| `API_KEY` | OpenAI 兼容 API 密钥 |
| `BASE_URL` | API 基础 URL（支持任何 OpenAI 兼容接口） |
| `MODEL` | 使用的模型名称 |
| `base_path` | Agent 文件操作的根目录 |
| `lang` | Agent 工具使用的语言，目前支持中文，英文，法语，俄语 |
| `break` | 重复指令处理方式，`true` 为直接中断任务，`false` 为拒绝但继续 |

你可以修改config_model.json对OpenAPI参数进行指定，如修改temperature:

```json
{
    "temperature": 1,
    "其他参数名": "其他参数"
}
```
注：此配置仅对支持该功能的大模型生效，如deepseek-v3.2不会因该参数的存在调节输出。

### 3. 启动

根据需求选择启动方式：

| 模式 | 启动命令 | 说明 |
|------|---------|------|
| 命令行模式 | `python CNMD.py` | 终端交互，直接输入命令 |
| Web UI 模式 | `python CNMD_webui.py` 或 `start_webui.bat` | 浏览器访问 `http://localhost:5000` |
| 微信模式 | `python CNMD_wechat.py` 或 `start_wechat.bat` | 微信扫码登录后通过微信对话 |

## 📌 核心概念

### 事件驱动模式

不同于传统的大模型对话，事件模式下大模型可选择操作 Agent 工具而不直接回答用户，并等待工具返回结果后继续执行，直到完成任务。从用户下达命令到大模型完成命令之间的过程为一个**事件**。

如仅对话，则一次回复即为一个事件。

### 节点操作

在每次事件开始前，可存档当前对话记录，随时回退到任意节点重新开始：

```text
    #node save eventb
          ↓
eventA-eventB-eventC-eventD->...
(init)    |
          | -> #node load eventb
          |
       eventE->eventF->....
      (->eventB)
```

### 用户命令

用户可直接输入以 `#` 开头的命令控制系统：

| 命令 | 说明 |
|------|------|
| `#node save <名称>` | 保存当前对话状态到指定节点 |
| `#node load <名称>` | 从指定节点加载对话状态 |
| `#node list` | 列出所有已保存的节点 |
| `#node backward <轮数>` | 回退指定轮数的对话（默认1轮） |
| `#mem save` | 提取当前对话的关键信息并保存到记忆数据库 |
| `#mem analyse` | 调用大模型对记忆数据库进行整理、去重和压缩 |
| `#bot reasoning on/off` | 开关思考内容返回 |
| `#bot reset` | 清空对话记录 |
| `#bot prompt <人设名>` | 切换人设 |
| `#backup` | 备份当前工作目录 |
| `#help` | 显示帮助信息 |

## 💬 三种使用模式详解

### 命令行模式

最基础的模式，在终端中直接与 CNMD 交互：

```bash
python CNMD.py
```

输入消息即可对话，输入 `#` 开头的命令执行系统操作。

### Web UI 模式

基于 Flask-SocketIO 的实时网页聊天界面，支持局域网多设备访问：

```bash
python CNMD_webui.py
```

- 访问地址：`http://localhost:5000`
- 局域网设备访问：`http://[服务器IP]:5000`
- 使用 `@bot` 前缀或 `#` 命令触发 Agent 处理
- 支持自定义昵称和气泡颜色
- 支持在线用户列表显示

> ⚠️ 如 5000 端口不可用，可尝试 8000/8080/3000 端口。由于使用 HTTP 协议，浏览器可能会显示安全提醒，属于正常现象。

### CLI模式

使用终端直接使用，可用于代码协助。

允许多行输入，输入指令后回车键入空字符(打两次回车)将指令传达至CNMD，可拖拽文件将地址复制到shell

允许使用#pause指令强制暂停工作。

### 微信模式

通过微信 iLink Bot API 接入微信，实现微信内与 Agent 对话：

```bash
python CNMD_wechat.py
```

- **首次启动**：终端显示二维码，使用微信扫码登录
- **凭证保存**：登录成功后凭证自动保存至 `wechat/credentials.json`，后续启动无需重新扫码
- **重新登录**：删除 `wechat/credentials.json` 后重启即可
- **支持消息类型**：文本、图片、语音（自动转文字）、文件、视频
- **文件自动下载**：接收的图片/文件/视频自动下载至 `./files/` 目录
- **文件发送**：Agent 可通过 `send` 指令向用户发送文件
- **定时提醒**：Agent 可创建定时器，到时自动发送提醒消息
- **停止回复**：发送 `#pause` 可强制终止任务

## 系统提示词自定义

允许对系统提示词进行自定义。

### 结构

系统提示词包含以下部分：
- 基础人设/persona：基础设定
- 基础能力/skills：基础agent工具
- 特殊规则/extra：额外规则，根据需要定制

以上均以md skill形式保存在prompt_loader目录下，根据需要配置。

### 配置方式

1.自行将人设文件(persona)，规则文件(extra)分别放置于对应目录，确保为md格式。
1.1人设可自行编辑，或使用Agent的人设提取模块辅助生成。
1.2建议使用默认工具文件。本项目使用自定义工具链，不支持tool calling api。
1.3三个文件均非必要，可在配置文件对应位置填"none"表示不存在该部分。建议保留基础人设。
2.在配置文件(./prompt_loader/config.json)中加入以下信息：

```json
"[你的预设名]":{
        "persona":"[你的人设文件名，不包含后缀]",
        "skills":"skill_base",//使用默认工具，不希望有该能力可以留空
        "extra":"[你的规则文件名，不包含后缀]"
    }
```
3.在程序中将cnm.set_prompt('agent_wechat')语句改为cnm.set_prompt('[你的预设名]')

## 🧠 记忆数据库系统 (Memory Database)

CNMD 内置了基于大模型辅助的记忆数据库系统，解决了大模型“阅后即焚”的问题，使 Agent 能够积累长期经验、记住用户偏好与历史工作流。

### 核心功能

- **智能记忆提取**：自动分析对话历史，提取用户信息、工作流、对话事件等关键要点，过滤无关紧要的短时信息。
- **持久化存储**：记忆以结构化的 JSON 键值对形式持久化保存在 `database/mem.json` 中。
- **混合检索机制**：结合 Jaccard 相似度算法与大模型语义匹配，确保记忆检索的高召回率与准确性。
- **自动整理与压缩**：支持对记忆库进行全局分析，合并同类项，剔除冗余信息，保持记忆库精简。

### 数据结构

记忆数据存储在 `database/mem.json` 中，采用扁平化的 JSON 键值对格式。键（Key）为信息类型或特征词，值（Value）为具体的记忆内容。

### 工作原理

1. **记忆保存**：系统将当前对话历史发送给大模型，大模型根据预设 Prompt 提取关键信息（分为对话事件类、用户信息类、工作流类等），并格式化为键值对写入 `mem.json`。
2. **记忆检索**：
   - **一阶检索**：系统计算查询关键词与记忆库中所有 Key 的 Jaccard 相似度，按得分排序返回。
   - **二阶语义兜底**：若一阶检索无结果，系统会将记忆库的所有 Key 发送给大模型，由大模型进行语义相关性判断，提取相关的 Key 并返回对应记忆。
3. **记忆整理**：系统将当前所有记忆发送给大模型，大模型对同类信息进行合并、总结，并丢弃不重要的短时信息，然后覆盖更新 `mem.json`。

### 使用指南

#### 用户命令
用户可通过以下命令手动管理记忆库：

| 命令 | 说明 |
|------|------|
| `#mem save` | 总结当前对话上下文，提取关键信息并存入记忆数据库 |
| `#mem analyse` | 对现有记忆数据库进行全局整理、去重和压缩 |

#### Agent 工具指令
在事件驱动模式下，Agent 可自主调用 `memory` 指令查询记忆：

- **指令格式**：`memory <关键词1> <关键词2> ...`
- **示例**：Agent 需要了解用户的技术背景，可执行 `memory 技术栈 偏好语言`，系统将返回匹配的记忆内容供 Agent 在后续对话或任务中参考。
